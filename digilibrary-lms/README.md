# DigiLibrary — LMS Backend (Part 1: physical books)

Stack: Node.js + Express, MySQL (InnoDB), JWT auth. Frontend and the e-book/PDF library come later.

## Setup
1. `npm install`
2. Copy `.env.example` to `.env` and fill in DB password and a long `JWT_SECRET`
3. `npm run db:init`  (creates database + tables + default loan rules)
4. `npm run seed:sample`  (first admin from .env + 4 demo books)
5. `npm run dev`  -> http://localhost:5000/api/health
Needs MySQL 8 (FULLTEXT + utf8mb4_0900_ai_ci, so searches are case-insensitive).

## Roles
| Role | Registration | Can do |
|---|---|---|
| admin | needs one-time code | everything: codes, roles, suspend, delete books, reports |
| librarian | needs one-time code | manage books/copies, members list, issue/return/renew, fines, all records |
| staff | needs one-time code | borrower; own history only |
| faculty | open | borrower; own history only |
| student | open | borrower; own history only |

Codes are generated by admin (`POST /api/registration-codes`), tied to one role, single-use, expire (default 7 days).
Every member gets a unique `member_code` (e.g. STU-2026-00012) used at the issue desk.
Required details by role: student = department, course, year, enrollment no.; faculty = department, employee id, designation; staff = department, employee id, designation, code; librarian = employee id, code; admin = code. Everyone gives name, email, address.

## API (all under /api, JWT in `Authorization: Bearer <token>`)
| Method + path | Who | Purpose |
|---|---|---|
| POST /auth/register, /auth/login | public | register / login |
| GET /auth/me, POST /auth/change-password | any | profile, password |
| POST/GET/DELETE /registration-codes | admin | one-time codes |
| GET /users, GET /users/:id | librarian/admin (own id for others) | find members |
| PATCH /users/:id | self (contact only) / admin (role, status) | edit |
| GET /books?q=&subject=&available_only=&page=&limit= | any member | search |
| GET /books/:id | any member | details: copies + serial nos, quantity, subjects, related books |
| GET /books/subjects/list | any member | subject filter list |
| POST /books, PATCH /books/:id, POST /books/:id/copies, PATCH /books/copies/:copyId | librarian/admin | catalogue |
| DELETE /books/:id | admin | only if no issue history |
| POST /issues {member_code, serial_no} | librarian/admin | issue a copy |
| POST /issues/:id/return {condition, extra_charge} | librarian/admin | return, fine calculated |
| POST /issues/:id/renew, /issues/:id/pay-fine | librarian/admin | renew, mark fine paid |
| GET /issues/my | any member | ONLY own history (id taken from token) |
| GET /issues?status=active/overdue/returned/unpaid_fine&member_code= | librarian/admin | all records |
| GET /reports/summary | librarian/admin | dashboard numbers |

## Search behaviour
- Matches title, author, ISBN, subject name, plus full-text relevance
- Order: exact title, exact ISBN, subject match, relevance, then A-Z
- Each result has `availability: {available, total, is_available}` for the right-hand column

## Gaps I filled
- Per-copy serial numbers (BK00012-001): availability = available copies out of total
- Loan rules per role in `loan_policies` (student 3 books/14 days/2 per day; faculty 10/30/1; staff 5/21/2). Edit rows to change.
- Issue checks: copy available, member active, limit not reached, no overdue books, no unpaid fines (`MAX_UNPAID_FINE`), no duplicate title. Row locks (`FOR UPDATE`) prevent two librarians issuing the same copy
- Fine = days late x rate (+ optional replacement charge), live for overdue books, fixed on return
- Renewals with limits, damaged/lost copies, member suspension, first-admin seed, login rate limit, password change, summary report

# Frontend (client/) — React + Vite

## Run (two terminals)
1. Server: `npm run dev` (port 5000)
2. Client: `cd client && npm install && npm run dev` -> http://localhost:5173
Vite proxies `/api/*` to port 5000, so no CORS setup is needed in development.

## Pages
| Route | Who | What |
|---|---|---|
| /login, /register | public | register form changes fields by role (student/faculty/staff/librarian/admin, code for privileged roles) |
| / | any member | search box, subject filter, "available only"; availability shown on the right of each result |
| /books/:id | any member | quantity, subjects, serial numbers and status of each copy, related books; staff can add copies / mark damaged or lost |
| /my-issues | any member | only the member's own history, filter by status |
| /desk | librarian/admin | issue by member code + serial no., find member, all records, return / renew / mark fine paid |
| /manage-books | librarian/admin | add book with subjects and number of copies |
| /admin | admin | summary numbers, registration codes, change role, suspend/activate |

Menu items and routes are hidden/guarded by role in the UI, but the real protection is on the server.

## Notes
- JWT is kept in localStorage; an expired token sends the user back to /login.
- For production: `npm run build` in client/ and serve `dist/` (or set the API base URL), and set `CLIENT_ORIGIN` in the server .env.
- Not yet run against a live server in my environment (no network there): do a first test with the sample data.
